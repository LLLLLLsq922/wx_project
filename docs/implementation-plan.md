# 分阶段实施计划

## 阶段一：共享基础与国标迁移审计

目标：保持现有国标页面可用，同时让其通过统一规则接口运行。

- 固化需求与架构文档。
- 建立玩法注册表、规范牌模型、数量校验和零和账本。
- 建立本地数据模式与迁移入口。
- 为现有国标实现增加适配器，页面不再直接依赖旧工具文件。
- 逐项建立国标番种清单、规则依据和覆盖矩阵。
- 修复审计发现的拆牌、等待与不计错误。
- 将首页升级为多功能入口，并把国标计算页迁入对应流程。

完成标准：现有测试全部通过；新增核心基础测试；国标番种覆盖矩阵无空项；真机页面功能不倒退。

当前状态：阶段一代码开发与国标规则审计已完成，80个非花牌番种覆盖矩阵无空项；自动测试全部通过。阶段关闭前仅剩微信真机回归验收。

## 阶段二：川麻

- 实现108张牌限制、定缺、换三张记录及三种玩法流程。
- 实现番种候选、复合与排除关系。
- 实现胡牌、杠的即时交易。
- 实现花猪、大叫、退税和牌墙耗尽结算。
- 实现川麻牌局轮庄、赛制和结果详情。
- 补齐规则与结算组合测试。

完成标准：所有已确认牌型和结算场景具有自动测试；总分守恒；三种玩法可完成整场。

当前状态：进行中。已接入统一规则注册表，完成108张牌、禁字牌/赤牌/吃牌、定缺清门、碰杠结构、胡牌张数、标准牌型/七对拆分与听牌余量校验；已实现首批番种组合、替代关系、根、门清/中张及事件附加番；已实现点炮、自摸两种配置、一炮多响以及直杠/补杠/暗杠的即时零和交易；已实现换三张同花色校验、每局随机方向记录、定缺准备流程，以及普通、血战到底、血流成河三种玩法的事件状态机与下一庄建议；已实现自动花猪判断、大叫最高静态番分析，以及按花猪、大叫、退税顺序执行的牌墙耗尽结算；已实现固定局数、自定义局数、每人坐庄一次和不限局数赛制，支持自动/人工轮庄、累计排名、负分、历史替换、撤销及确定性重放。下一步接入川麻创建牌局、算牌、局内录入和结果页面，并连接本地草稿与历史存储。

规则审计备注：按“每种牌最多四张”和“将对只能使用2、5、8且必须为对对胡”的既定约束，清将对无法构造合法的四面子一将牌例。当前保留规则目录项，但不放宽牌张上限；在规则来源复核前不生成非法命中。

## 阶段三：日麻

- 实现标准手牌拆分、役种候选、门清与副露减番。
- 实现符、基本点、上限、役满、宝牌及赤牌。
- 实现振听、立直棒、本场棒、多家荣和和包牌。
- 实现荒牌、途中流局、流局满贯与终局条件。
- 实现东风战、半庄、自定义局数及最终顺位分。
- 补齐役种、番符、支付和牌局状态测试。

完成标准：完整役种覆盖矩阵无空项；典型番符牌例与边界支付结果通过；整场流程可重放。

## 阶段四：牌局管理、历史与分享

- 完成多场进行中牌局、实时草稿和恢复。
- 完成历史搜索筛选、重新打开、撤销和中段纠错重算。
- 完成人工调整及逐笔公式明细。
- 完成走势图、单局图、整场战绩图和相册分享。
- 完成存储空间、迁移失败和分享权限的异常体验。
- 进行包体积审计、分包调整与真机验收。

完成标准：重启恢复、纠错重算、迁移和分享均通过测试；主包及静态资源满足微信建议；无横向滑动。

## 提交流程

每个阶段结束前依次执行：

1. 运行全部自动测试。
2. 检查未提交差异，排除用户无关修改。
3. 汇总规则覆盖、已知限制和真机待验项。
4. 生成单一、清晰的阶段提交。
5. 经用户要求后推送并同步到 `master`。
