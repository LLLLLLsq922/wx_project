# 分阶段实施计划

## 阶段一：共享基础与国标迁移审计

目标：保持现有国标页面可用，同时让其通过统一规则接口运行。

- 固化需求与架构文档。
- 建立玩法注册表、规范牌模型、数量校验和零和账本。
- 建立本地数据模式与迁移入口。
- 为现有国标实现增加适配器，页面不再直接依赖旧工具文件。
- 逐项建立国标番种清单、规则依据和覆盖矩阵。
- 修复审计发现的拆牌、等待与不计错误。
- 将首页升级为多功能入口，并把国标计算页迁入对应流程。

完成标准：现有测试全部通过；新增核心基础测试；国标番种覆盖矩阵无空项；真机页面功能不倒退。

当前状态：阶段一代码开发与国标规则审计已完成，80个非花牌番种覆盖矩阵无空项；自动测试全部通过。阶段关闭前仅剩微信真机回归验收。

第一、二阶段的开发者工具与真机执行清单见[外部验收测试手册](./phase1-phase2-external-test-plan.md)。

## 阶段二：川麻

- 实现108张牌限制、定缺、换三张记录及三种玩法流程。
- 实现番种候选、复合与排除关系。
- 实现胡牌、杠的即时交易。
- 实现花猪、大叫、退税和牌墙耗尽结算。
- 实现川麻牌局轮庄、赛制和结果详情。
- 补齐规则与结算组合测试。

完成标准：所有已确认牌型和结算场景具有自动测试；总分守恒；三种玩法可完成整场。

当前状态：阶段二代码开发已完成。规则引擎、即时/终局结算、换三张与三种玩法状态机、四种整场赛制、轮庄排名及历史重放均已闭环；川麻分包已提供快速算牌、创建牌局、规则配置、进行中牌局列表、已结束牌局历史、牌局总览和开始/恢复当前局。快速算牌支持完整暗手和碰/直杠/补杠/暗杠、和牌张、定缺、规则开关与附加番种，自动展示13张听牌分析、14张最高番和其他拆分，并可从命中番种直接进入对应规则详情。当前局页面已实现四家换三张、四家定缺、完整手牌胡牌、自摸、点炮、一炮多响、杠牌即时录入和本局分数展示；牌墙耗尽流程支持逐家录入未和牌玩家的13张终局结构、跨玩家四张上限校验，并结合定缺与可见牌自动执行查花猪、查大叫及杠分退税。局内和历史单局可展示事件时间线、和牌牌面、逐笔支付方向与公式；提交单局前可人工纠正下一庄，不限局数赛制可在无当前局草稿时手动结束整场。规则百科提供关键字和番数筛选、成立条件、不成立情况、不重复计算关系及牌面示例。阶段关闭前仅剩微信开发者工具编译与真机完整流程验收。

规则审计备注：按“每种牌最多四张”和“将对只能使用2、5、8且必须为对对胡”的既定约束，清将对无法构造合法的四面子一将牌例，因此不作为独立牌型；规则引擎与百科保留可成立的清对、将对，不放宽牌张上限。

## 阶段三：日麻

- 实现标准手牌拆分、役种候选、门清与副露减番。
- 实现符、基本点、上限、役满、宝牌及赤牌。
- 实现振听、立直棒、本场棒、多家荣和和包牌。
- 实现荒牌、途中流局、流局满贯与终局条件。
- 实现东风战、半庄、自定义局数及最终顺位分。
- 补齐役种、番符、支付和牌局状态测试。

完成标准：完整役种覆盖矩阵无空项；典型番符牌例与边界支付结果通过；整场流程可重放。

## 阶段四：牌局管理、历史与分享

- 完成多场进行中牌局、实时草稿和恢复。
- 完成历史搜索筛选、重新打开、撤销和中段纠错重算。
- 完成人工调整及逐笔公式明细。
- 完成走势图、单局图、整场战绩图和相册分享。
- 完成存储空间、迁移失败和分享权限的异常体验。
- 进行包体积审计、分包调整与真机验收。

完成标准：重启恢复、纠错重算、迁移和分享均通过测试；主包及静态资源满足微信建议；无横向滑动。

## 提交流程

每个阶段结束前依次执行：

1. 运行全部自动测试。
2. 检查未提交差异，排除用户无关修改。
3. 汇总规则覆盖、已知限制和真机待验项。
4. 生成单一、清晰的阶段提交。
5. 经用户要求后推送并同步到 `master`。
